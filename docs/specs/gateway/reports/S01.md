## Deviations from the spec or AWS, with reasons

- Pipeline table lists `resourcePolicy` twice (rows 8 pre-auth, 10 post-auth). The registry
  uses two modules, `resourcePolicy:pre` and `resourcePolicy:post`, so each slot keeps the
  `name` + `run(ctx)` contract and S07 can replace each body independently.
- `BAD_REQUEST_PARAMETERS` default message is `"Invalid request parameters"`. The spec's
  default-message list has no entry for it; this mirrors the `BAD_REQUEST_BODY` wording.
- `DEFAULT_4XX`/`DEFAULT_5XX` carry `status: null` and render as 400/500. S06 owns real
  fallback resolution.
- `EXPIRED_TOKEN`/`INVALID_API_KEY`/`INVALID_SIGNATURE`/`WAF_FILTERED` all default to
  `"Forbidden"` (403), matching AWS's generic 403 bodies until owning specs customize.
- Token-bucket semantics fixed as: `rate` = tokens/second, `burst` = capacity, buckets
  start full, `retryAfterMs = ceil((cost - tokens) / rate * 1000)`. The spec left units
  implicit; this is documented on both implementations.
- `LIMITS` are S01 defaults (10 MB body, 10 KiB header values, 8192-char URLs, 100 headers);
  enforcement and per-protocol tuning belong to S15, so S01 exposes pure predicates only.
- The unmatched-request fallback lives in `runPipeline` (REST → 403
  `MISSING_AUTHENTICATION_TOKEN`, HTTP → 404) until S03's `match` phase replaces it.
- `ports.mjs` contains typedefs only (`export {}`); `createPorts` defaults live in
  `core/index.mjs`.
- No DB tests: S01 has no migrations or DB code, so there is nothing to gate on
  `PODS_TEST_DB_URL`.
