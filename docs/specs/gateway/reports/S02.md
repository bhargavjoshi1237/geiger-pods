## Deviations from the spec or AWS

1. `tests/access.test.mjs` ("every inherited role is read-only") contradicted
   S02 §1 (`owner: ["*"]`, admin all-but-grant). Replaced that one test with
   the S02 matrix (owner full, admin all-but-`role.grant`, manager build/
   release/support, member read-only); null-identity fail-closed kept.
2. `pods.usage.view` / `pods.audit.view` serve double duty as section-view and
   Consumers/Operations keys (one key, one definition — the catalog forbids
   duplicates). Noted in the config.
3. RLS uses hand-written `pods.can(...)` policies instead of `toSqlPolicies`:
   the compiler emits grant-only predicates and cannot express the inherited
   system-role half. Same enforcement point, stronger predicate.
4. Granting requires holding each key unscoped-or-inherited, in both
   `assertCanGrant` and `pods.grant_role()` (a scope-restricted holding can
   never authorize granting — prevents scope escalation through direct RPC).
5. Unknown-field rejection (422) in `validate` instead of stripping, so
   misspelled keys cannot vanish silently.
6. Wrapped-DEK envelope packs wrap coverage IV+tag+ciphertext into the single
   `wrapped_dek bytea` (60 bytes: 12 IV ‖ 16 tag ‖ 32 DEK) — no schema change.
7. PEM kinds fingerprint as cert SHA-256 (a PEM's last 4 chars are `----`).

  in this environment (adding `pg` as a devDependency is the recorded need).
  Migrations were transcribed exactly (rbac body byte-identical to
  `migrationSql("pods")` minus the two removed policies; `@up`/`@down`
  present; drift test pins the generated block), but they have never been
  applied — `db:push`/rollback and the three `[db]` tests still need a real run.

  is editing it concurrently); updating it is a merge step, not done here.
- `public.roles` product-role rows are not seeded (S02 defines no roles
  endpoint): Team-access grants require an existing project role row; the
  management API returns 404 until roles are seeded (S14 or an admin job).
- Supabase adapter details need live verification: bytea-as-`\x`-hex over
  PostgREST, cross-schema role embeds (worked around with two queries),
  `schema("pods").rpc(...)` (exists on the client, untested against server).
- UI screens were lint- and export-checked only (no `next dev`/browser run
  per instructions); loading/empty/error/denied states are implemented.
- Did not touch: `package.json`/`package-lock.json` (S01 agent's concurrent
