## Files created

Engine (`lib/gateway/core/integrations/`):

- `uri.mjs` — `{param}` / `${stageVariables.x}` / `${request.path.x}` rendering,
  greedy slash preservation, per-segment percent-encoding, HTTP `$default`
  path-append, `API_CONFIGURATION_ERROR` on empty host / non-http(s).
- `headers.mjs` — outbound header build (strip hop-by-hop + `x-pods-*`, `host`,
  `X-Forwarded-For` append, `X-Forwarded-Proto/Port`, HTTP `Forwarded`,
  `traceparent` propagation) and response sanitize with `x-pods-remapped-*`.
- `ssrf.mjs` — pure-JS IP classification (loopback, RFC1918, link-local incl.
  metadata IP, CGNAT, `0.0.0.0/8`, ULA, link-local v6, IPv4-mapped forms,
  self-hosts), guarded lookup + `toConnectLookup` for undici `connect.lookup`
  (rebinding-safe; checked on every connection).
- `node-http.mjs` — Node-only networking kept out of `http.mjs`: default DNS
  resolver and `createHttpDispatcher` (guarded lookup + TLS options).
- `http.mjs` — `HTTP`/`HTTP_PROXY` adapter: timeout `AbortController`, client
  abort linkage, no redirects, 10 MB buffered cap.
- `mock.mjs` — `MOCK` adapter (status from rendered template, default 200).
- `function.mjs` — REST 1.0 + HTTP 1.0/2.0 event builders, 1.0 strict parse,
  2.0 inference (string/object-without-statusCode/cookies), webhook HMAC
  sign/verify, `aws_lambda` SigV4 Invoke, `selection_pattern` matching.
- `aws.mjs` — `AWS_SUBTYPES` table (10 first-class subtypes) + builders for
  subtype and generic REST action/path requests.
- `connector.mjs` — tunnel framing (4-byte streamId data frames, JSON control
  frames, 256 KB credit window), allow-list check, gateway `createHub`
  (round-robin, ping/dead tracking, AVAILABLE/DEGRADED/FAILED/PENDING,
  `acceptAgentSocket` for the S05 runtime), `invoke` through the tunnel.
- `backend-auth.mjs` — vault injection (`header`/`bearer`/`basic_auth`/`query`/
  `oauth_client_credentials`/`aws_sigv4`/`client_certificate`), 60 s secret
  cache, KV-cached OAuth tokens with one 401 refresh+retry, `****` masking.
- `index.mjs` — `invoke` dispatcher on `type` + `CONNECTOR` routing, per-protocol
  error mapping (§3.6), `$context.integration` recording.
- `lib/gateway/core/auth/sigv4.mjs` — `signRequest` (signer only; S07 adds
  verification in the same file). WebCrypto, no Node-only APIs.

## Deviations from the spec or AWS, with reasons

1. **Wire statuses beyond the S01 catalog** (HTTP 503/500, REST 502 for
   malformed/oversize function results): `mapInvocationError` sets an explicit
   `statusCode` override on the `GatewayError`; the `invoke` phase renders it
   (`type` still drives `$context`/`x-pods-error-type`). The S01 catalog has no
   502/503 entries and is S01-owned.
2. **`timeout_ms` raise to 300000 not implemented.** `project_settings` (S02)
   has no `max_integration_timeout_ms` key; validation caps at 29000
   (REST/WS) / 30000 (HTTP). Deferred to S05/S15 with the stage context.
3. **FUNCTION custom request rendering** arrives via `outbound.renderedTemplate`
   (S06 owns templates); the engine consumes it, selection matching is live.
4. **Agent buffers the request body** until `end("request")` before one private
   `fetch`; response bodies stream under the 256 KB window. Full-duplex
   streaming proxy is documented as future work in `PROTOCOL.md`.
5. **Per-request undici `Agent`** (no shared pool) — correct isolation of TLS
   + SSRF guard per integration; pooling is a later perf pass.
6. **`PODS_ALLOW_LOOPBACK=1` / `integration.allowLoopback`** test escape hatch:
   permits loopback only (RFC1918/metadata still blocked); never set in prod.
7. **OAuth `expires_in - 60 s` floor at 0**; in-process secret cache uses
   `Date.now` (60 s wall-clock, not the injected KV clock) — documented.
8. `getApiProtocol` resolves S03 API refs by uuid **or** `public_id`.

  here (same recorded need as S02). The migration is written exactly
  (`@up`/`@down`, FK checked against S03's `20261006000301_catalog.sql`,
  RLS mirrors S02 patterns) but never applied; the `[db]` RLS test skips
  without `PODS_TEST_DB_URL`; adapter methods are unexecuted against Postgres.
- **`parity-status.md` not updated**: S01-owned with concurrent editors (same
  call as S02 made); left for the merge step.
- **UI verified by lint only** (no `next dev` per instructions); loading,
  empty, error and denied states are implemented; `IntegrationsTab` and
  `ClientCertificatesCard` are intentionally unregistered until the
  orchestrator wires them into API detail/settings.
- **Invoke success path needs S06**: `ctx.integrationResult` is produced, but
  until S06's `integrationResponse`/`methodResponse` render it, end-to-end
  pipeline responses still fall through to the S01 stub fallback.
- No secrets in code: test fixtures use obviously-fake values
  (`sk-live-…` in `backend-auth.test.mjs` is a local dummy, never a real key);
  error paths assert `****` masking.
