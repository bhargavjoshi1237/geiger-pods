## Findings

| Severity | File:line | Defect | Status |

| critical | `app/api/v1/projects/[projectId]/apis/[apiId]/resources/[resourceId]/methods/[httpMethod]/route.js:6` | `methodArgs(params, extra = {})` returned `projectId: extra.projectId` (always `undefined` — no caller passes `extra`), and every handler spreads it **after** the real id (`{ projectId, ...methodArgs(params) }`), clobbering `projectId` with `undefined`. All four method endpoints (GET/PUT/PATCH/DELETE) therefore resolved the API with `projectId: undefined` → 404 for every request. Service-level tests never caught it because they call services directly. | **fixed** + `S03 review: method routes keep projectId` (evals the shipped helper from the route file and asserts the spread preserves `projectId`). | high | `lib/control/rest-resources.mjs:287` (`deleteResource`) | No root guard: `DELETE …/resources/{rootId}` succeeded without `recursive` and deleted **only** the root row (`deletedResources: 1`), because the descendant prefix `${row.path}/` becomes `"//"` which matches nothing. The `/pets` branch was left orphaned (parent points at a soft-deleted root). With `recursive=true` the same orphaning occurred. AWS does not allow deleting the root resource, and this repo's own UI already hides the delete button for `/`. | **fixed** + `S03 review: root resource cannot be deleted` (asserts 422 with and without `recursive`, and that `/` + `/pets` survive). | medium | `lib/control/apis.mjs:417` (`cloneApi`) | Fail-open method copy: `resource_id: idMaps.resources.get(method.resource_id) ?? method.resource_id` reused the **source** API's resource id when the mapping missed, pointing the cloned method at another API's resource. Demonstrated with a draft whose method references a missing resource: clone failed with a misleading 409 (unique-index collision with the source row) **after** partially inserting the target API + resources. | **fixed** + `S03 review: clone aborts on methods with missing resources` (asserts 500 and no `"(copy)"` residue). Fix: validate all `method.resource_id` values against the source resource set **before** `insertApi` (fail before side effects), reuse the already-fetched rows, and throw on a missing mapping at copy time instead of falling back. |

By direct SQL, an update-only holder can soft-delete (set `deleted_at`) and a delete-only holder can edit rows; only the service layer enforces the exact key. | **reported-not-fixed**: distinguishing edit vs soft-delete needs an OLD/NEW comparison in policy, and verification needs a live Postgres (`PODS_TEST_DB_URL` unset here). A crash between steps leaves partial state. | **reported-not-fixed**: the db port has no transaction primitive; fixing needs a cross-spec (S02) change. Happy-path behavior is correct. |

## Areas checked with nothing significant to report

- **Matcher correctness.** Verified by probe in addition to the existing suite: AWS priority table, exact-beats-`ANY`, `ANY`-only serving unmatched methods, greedy requiring ≥1 segment, literal-beats-param left-to-right (HTTP) and REST backtracking (`/a/x/c` → `/a/x/{d}`), longest-greedy-prefix winning, full-match round beating greedy regardless of method specificity, one-trailing-slash ignored (REST) vs significant (HTTP, documented deviation), case-sensitivity, post-match `%2F`-in-one-param decoding, `HEAD`≠`GET` with `ANY` cover, REST miss → 403 `MISSING_AUTHENTICATION_TOKEN` / 404 with `missing_route_behavior=not_found`, HTTP miss → 404. All match the spec and S01 §3 status codes.
- **Security.** No secret handling in S03 scope (artifact-secret rules are S02/S04); no timing-sensitive comparisons; regexes are anchored/linear (no ReDoS); `Object.keys` unknown-field rejection plus spread-only copies make `__proto__` injection inert; `decodeParam` falling back to raw text on malformed escapes is the documented, safe choice. The trigger `pods.rest_resource_path()` is not `SECURITY DEFINER`, so the `search_path` hardening note does not apply (same for the `touch_updated_at` triggers, which are S02-owned).
- **Contract stability.** `match/` exports, `name`+`run(ctx)` phase contract (phase file itself untouched per rules), `CLONE_HANDLERS`/`registerCloneHandler`, `provisionQuickCreateTarget` stub, `parsePaging`/`toPage`, and view shapes all match what S05/S06/S13 need. `quickCreate` remaining half-done is honestly disclosed in the report and blocked on S04/S05 — not a defect.
- **Tests.** The S03 tests assert real behavior (no tautologies, no mock-only assertions); the 100 ms perf guard is intentionally looser than the 1 ms spec target per the spec's own no-flake rule, with the true p99 printed; the `[db]` test skips honestly without `PODS_TEST_DB_URL`.
