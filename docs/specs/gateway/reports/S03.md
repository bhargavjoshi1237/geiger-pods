## Deviations from the spec or AWS, with reasons

1. **Match phase lives in `phases/match.mjs`** (S01 stub replaced) rather than only `match/` — the pure matchers stay dependency-free; the phase is the specified pipeline wiring for them.
2. **Permission checks in services, not route options** — `pods.route.write` is API-scoped and the URL carries the public id; services resolve to uuid first, then check. Same enforcement point, correct scope value.
3. **Path trigger fires on INSERT and parent/path_part updates** (not every UPDATE), so branch-rename rewrites don’t fight it; the service recomputes descendant paths explicitly and identically.
4. **HTTP trailing slash is significant** (`/pets/` ≠ `/pets`); only REST ignores one trailing slash, per the spec’s silence on HTTP.
5. **Ambiguous same-shape HTTP routes** (`GET /pets/{a}` vs `GET /pets/{b}`) resolve by definition order — AWS-ambiguous case, kept deterministic; REST forbids it (409).
6. **Malformed percent-escapes in params fall back to raw text** instead of failing the match.
7. **WS-only route columns are 400 `capability_unsupported` on HTTP** (`requestParameters`, `requestModels`, selection expressions); `apiKeyRequired: true` is 422 outside WS/REST-methods.
8. **`updateApi` gates merged existing+patch values** so capability checks see the effective row, not just the patch.
