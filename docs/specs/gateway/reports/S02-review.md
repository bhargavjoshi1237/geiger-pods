# S02 review — Data foundation (defects found and fixed)

Date: 6 October 2026. Reviewer scope: spec `docs/specs/gateway/02-data-foundation.md`,
report `docs/specs/gateway/reports/S02.md`, every file that report lists, and `tests/s02/`.
Next.js code checked against Next 16.3.8 conventions where applicable (awaited
`params`, `await cookies()`, `runtime = "nodejs"` — all correct in the S02 routes).

## Findings

| Severity | File:line | Defect | Status |
|---|---|---|---|
| high | `supabase/migrations/foundation/20261006000102_authz_functions.sql:140` | `pods.grant_role()` never checks `pods.role.grant`. Spec §3 requires "insert/update requires `pods.role.grant`" enforced **in the function**, and `revoke_grant()` in the same file does check it. Any authenticated caller holding a role's keys (e.g. manager/admin, who hold keys but lack `role.grant`) could call the RPC directly and delegate permissions — including to non-members — bypassing the owner-only grant control. The JS service layer was safe (route + service both check); only the SQL path was open. | **Fixed** + test `S02 review: pods.grant_role SQL requires pods.role.grant`. Added the same `pods.can('pods.role.grant', …)` guard `revoke_grant` uses. |
| medium | `lib/control/secrets.mjs:146`, `lib/vault/secrets.mjs:215,246` | Secrets-row `version` was never incremented by any mutation (update, rotate, delete), so `If-Match`/409 lost-update protection (S01 §8) was theater: a stale `PATCH` after any concurrent change always succeeded. Settings got this right (`version: currentVersion + 1`); secrets did not. Snapshot `secrets-responses.json` confirmed it (`patched.version: 1`, `rotated.version: 1`). | **Fixed** + tests `S02 review: stale If-Match on secret PATCH conflicts after the row changed`, `S02 review: rotating a secret bumps the metadata version so PATCH guards stay sound`. Every secrets-row mutation now bumps `version`. Committed snapshot updated (`patched: 2`, `rotated/disabled: 3`). |
| low | `lib/control/secrets.mjs` (`assertExpiresAt`) | `expiresAt` was accepted as any string and passed to a `timestamptz` column, so `expiresAt: "not-a-date"` died in Postgres as a 500 instead of 422 per the S01 error conventions. | **Fixed** + test `S02 review: secret expiresAt rejects non-date strings with 422` (`Date.parse` gate on create and patch paths; valid ISO still passes). |
| low | `lib/control/validate.mjs:94` | Unknown-field rejection used `key in shape`, which is true for `"__proto__"`/`"constructor"` via the prototype chain — those keys were silently dropped instead of 422, contradicting the report's own deviation #5 ("misspelled keys cannot vanish silently"). | **Fixed** + test `S02 review: validate rejects __proto__ as an unknown field instead of dropping it silently` (`Object.hasOwn`). Verified no schema in the repo uses such field names. |
| low | `lib/control/audit.mjs` (`redact`) | `out[key] = …` with key `"__proto__"` invokes the prototype setter instead of storing an own property (prototype pollution of the redacted copy). Not reachable with attacker-controlled keys in S02 today (settings `features` is 422-blocked, scopes are regex-gated), but `redact` is the shared writer every later spec will pass user JSON through. | **Fixed** + test `S02 review: audit redact keeps __proto__ as an own property without touching the prototype` (`defineProperty` for `__proto__`; redaction semantics unchanged). |
| medium-low | `supabase/migrations/foundation/20261006000102_authz_functions.sql` (`pods.audit`) | `pods.audit()` is executable by any authenticated user with no membership or permission check, so audit rows for any project can be forged by direct RPC (noise/cover-tracks; rows can't be altered or deleted thanks to append-only). | Reported-not-fixed: the spec sentence ("users can never insert arbitrary rows") sits in the RLS-policy paragraph and is satisfied at the table layer (no DML policies); a correct full fix needs per-action permission design, and a partial `is_member` gate could break future system callers. Recommend S15 hardening decide: membership gate or service-role-only writes. |
| medium-low | `components/internal/screens/secrets/secrets_screen.jsx` | Spec §7 requires list columns (name, kind, fingerprint, current version, **last rotated**, used-by) plus create/rotate/**disable version**/delete-with-used-by-blocker. API surface is complete. | Reported-not-fixed: UI-only gap, and UI changes cannot satisfy the required failing-then-passing `node --test` regression in this harness (`next dev`/browser runs are prohibited). |

Correct today (S04 tables absent → 0 is right, as the S02 report discloses), but once S04 tables exist any real query failure silently reads as "unused" and the delete blocker fails open. | Reported-not-fixed: narrowing to missing-table-only needs live PostgREST error-code verification (db commands prohibited); S04 owns those tables and its report already claims the extension. |

## Areas reviewed with nothing significant to report

- **Vault crypto** (`lib/vault/crypto.mjs`, `keys.mjs`): AES-256-GCM envelope + wrap, random DEK/IV per version, AAD `project:secret:version`, KEK rotation via rewrap — correct; existing tamper/AAD/KEK tests are strong and genuinely exercise decryption.
- **RLS policies** for `project_settings`, `secrets`, `secret_versions` (column-grant approach is *stronger* than the spec's "revoke" wording), `audit_events` select, `role_grants` member-only select: `USING`/`WITH CHECK` placement correct, fail-closed defaults. `set search_path = ''` present on all new security-definers; `CREATE INDEX` names correctly resolve to the table schema (no rollback orphan issue).
- **Permission catalog**: 50 keys verified (11 views + 12 `scopeBy: "api"` + 27 project-scoped); owner/admin/manager/member matrix matches spec §1, including the `usage.view`/`audit.view` double-duty note.
- **Management API wiring**: every S02 endpoint enforces the spec's permission table; `needsService` used exactly on the vault-write paths; error mapping never leaks values; 6 MB cap, `If-Match` parsing, cursor clamping (1–100) all correct.
- **Screens/registry/sidebar/page**: 11 sections, `resolveScreen` nesting + tab allowlist, `resolveSection` contract preserved, view-gating intact.
- **Secret hygiene**: all views metadata-only (snapshot-enforced), audit redaction regex matches the spec exactly, no ReDoS/timing-unsafe comparisons found (regexes linear and anchored; no secret comparisons anywhere).
- **Test quality**: `rbac-sql` (exact SQL equality), vault tamper matrix, snapshot + forbidden-key scan are real tests, not tautologies. The `migrations.test` "revoke select" assertion passes via the `@down` block — weak but the `@up` column-grant construction is verified correct by reading.
- **Out of scope / already disclosed**: 3 db-gated tests skipped (no live Postgres, unrunnable per instructions), `parity-status.md` untouched (S01-owned), product-role seeding pending (S14/admin job). `public.roles` rows and token actors (401 fail-closed) behave as designed for this wave.
- **Neighbor suites**: `tests/s03` + `tests/s04` show 3 failures, all `S03 review:` tests from a concurrently-running S03 review agent against S03-owned files (`lib/control/apis.mjs`, method route files). None touch S02-edited code paths; verified independent of this review's changes.
