## Deviations from AWS, with reasons

1. **`ws` library for framing (justified).** Hand-rolling RFC 6455 risks
   interop bugs (masking, fragmentation, control frames). `ws@8.22.0` is
   small, maintained and already a dependency; limits/timers/auth stay in
   our code. No new dependency added.
2. **32 KB frame quota enforced at the reassembled-message level.**
   `ws` caps reassembled messages at 128 KB (`maxPayload` → 1009) and
   accepts fragmented 100 KB; single frames 32–128 KB are accepted
   leniently instead of 1009. Safe (never breaks valid clients);
   strict per-frame accounting is S15 hardening (new follow-up F37).
3. **Subprotocol negotiation is accept-only.** `$connect` integration
   responses carrying `Sec-WebSocket-Protocol` are not echoed yet (no
   test needs it); the handshake completes with no subprotocol (AWS
   default when none is selected).
4. **Load test is scaled by default.** Full 5,000 conns / 1,000 msgs runs
   behind `PODS_LOAD_TESTS=1`; default is 150/150 asserting the same
   relaxed 500 ms p99 (measured 18 ms). Sequential POSTs (≈67/s), not
   parallel 1,000/s — p99 is asserted, rate is reported.
5. **Control-plane connections mirror needs a runtime sender.** Without
   an injected `sender` it 410s (KV registry is data-plane-only). UI/CLI
   work once the control plane is wired to a gateway URL (follow-up F38).
6. **No `routeResponses` compile validation.** Draft `routeResponses`
   pass through to the artifact; unknown route ids fail at runtime, not
   deploy. Validation is S15 hardening.
7. **Quota counts throttle-phase only.** `$connect` + each message run
   the shared throttle/quota phases against the connect-time key; WS
   usage rollups reuse the S10 event (no separate usage export).
